# AGENTS.md — repository entrypoint

Read `AGENTS_BASE.md` first. Its existing repository rules remain binding. The rules below are an additional higher-priority layer when the user designates a working baseline or a structural benchmark. If they conflict with a generic deletion/compression heuristic in `AGENTS_BASE.md`, these rules govern.

## Protected baseline / 底本

When the user designates a prose, transcription, control, or other working state as a **baseline / 底本**, record the exact canonical file and commit or version before the next substantive pass.

- **Deletion is user-consent-gated.** Unless the user explicitly instructs deletion of an identifiable sentence, paragraph, passage, section, source item, quotation, qualification, transcription unit, or other protected part in the current conversation, later work may not delete, silently omit, demote away, or replace away baseline material merely for concision, elegance, flow, architecture, benchmark matching, cleanup, or compression.
- The baseline protects **content and evidentiary pins, not wording**. Rewriting, sentence merging/splitting, subordinate syntax, paragraph-boundary changes, and transition work are allowed when factual material, source ownership, quotations, qualifications, chronology, and inferential hinges remain recoverable.
- All future work starts from the latest descendant of the protected baseline. Never regenerate from a retired draft, old control, summary, benchmark note, or model memory unless the user explicitly restores it.
- After any substantial pass, compare against the immediately previous state and, where deletion risk exists, against the protected baseline. Restore any protected item that disappeared without explicit deletion authorization.

## Structural benchmark: strict sentence-by-sentence method

When the user selects an external article, chapter, or other text as a structural benchmark, use the actual controlled full text and proceed **one benchmark sentence → one project sentence at a time**.

- Determine what each benchmark sentence does: fact, background, subordinate qualification, contrast, causal link, retrospective qualification, source limit, transition, restatement, or another rhetorical load.
- **Move architecture, not content.** Preserve this project's evidence order, chronology, actors, and source ownership. Do not move later project material forward to fill an earlier benchmark slot, and do not import the benchmark's substantive claims or wording.
- Settle each sentence in the live text before advancing to the next benchmark sentence. Do not rewrite a whole paragraph first and retroactively claim correspondence.
- Paragraph boundaries follow **event completion**. Match sentence load, not sentence length alone: when the benchmark carries fact plus concession, cause, source limit, or retrospective qualification, test whether the project's already-existing qualification belongs in the same sentence.
- Benchmark matching never authorizes deletion of protected baseline material.

Compact rule: **protect the designated 底本; then move only architecture, one settled sentence at a time, never using style or compression as permission to delete protected evidence.**
